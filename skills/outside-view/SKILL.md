# Outside View

Inside views explain why this case might work. Outside views ask what tends to happen to cases structurally similar to this one.

Use both. Do not replace one bias with another.

## Workflow

1. Summarize the inside view.
   What mechanism makes the user expect the desired result?

2. Define candidate reference classes.
   Prefer structural similarity over superficial topic similarity. Consider:
   - same user behavior,
   - same business or incentive structure,
   - same technical dependency,
   - same organizational coordination burden,
   - same adoption pattern,
   - same maturity stage.

3. Check whether reference-class evidence is actually available.
   If tools and external sources are available, search for relevant cases or statistics.
   If not, say that the base rate is unknown rather than inventing one.

4. Compare inside and outside views.
   Ask:
   - which features are genuinely exceptional,
   - which claimed exceptions are merely hoped-for,
   - what common failure or success mechanisms transfer,
   - where the analogy breaks.

5. Use multiple reference classes when the choice of class changes the conclusion.

6. Convert the comparison into tests.
   Identify what evidence would justify treating this case as different from the reference class.

## Rules

Never fabricate a base rate.

Do not cite one famous success or failure as if it were a distribution.

Do not assume "similar industry" means "similar causal structure."

Separate measured base rates, anecdotal analogies, and speculative parallels.

## Output

Return:
- Inside view
- Candidate reference classes
- What the outside evidence suggests
- Where analogies break
- What would justify an exception
- Remaining uncertainty
